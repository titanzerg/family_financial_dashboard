# Family Finance Dashboard — Module 1 (สรุปสินทรัพย์รายเดือน)

ทำตาม [spec_v0.3.md](spec_v0.3.md) — บันทึกยอด **เดือนละครั้ง** ของแต่ละบัญชี (จดหลังโอนแบ่งเงินเดือนเสร็จ), ขั้นตอน **จัดสรรเงินเดือน**
ที่คิดยอดโอน A-2/A-3/A-1/LH ให้, สรุปยอดรายบัญชี/กลุ่ม/รวม, เทียบกับเดือนก่อนหน้า และแดชบอร์ด
(spec เดิม: [spec.md](spec.md) v0.1, [spec_v0.2.md](spec_v0.2.md) — ต้นเดือน/ปลายเดือน ถูกแทนที่แล้ว)

## วิธีรัน

ต้องมีแค่ Python 3.10+ (ไม่ต้องติดตั้งแพ็กเกจเพิ่ม)

```bash
python3 server.py
# เปิด http://127.0.0.1:8765
```

- ข้อมูลเก็บที่ `data/finance.sqlite` (เปลี่ยนได้ด้วย `FINANCE_DB=...`, พอร์ตด้วย `FINANCE_PORT=...`)
- ไฟล์สำรองอัตโนมัติอยู่ที่ `data/backups/` — สำรองวันละครั้งตอนเปิดโปรแกรม, ก่อนอัปเกรดโครงสร้างฐานข้อมูล, ก่อนย้ายกลุ่ม/ปิดใช้งานบัญชีหรือกลุ่ม และก่อนกู้คืนข้อมูล
- อัปเกรดจาก v0.1/v0.2: ยอดรายเดือนเดิม (v0.2 = ยอดปลายเดือน) ใช้ต่อ; ยอดต้นเดือนและรายรับของ v0.2 ย้ายไปเก็บในตาราง `legacy_v2_*` (ไม่ลบ) และระบบสำรองไฟล์เดิมไว้ก่อน (`*-before-migrate-v3.sqlite`)
- เซิร์ฟเวอร์รับการเชื่อมต่อจากเครื่องตัวเองเท่านั้น (127.0.0.1)

รันเทสต์: `python3 -m unittest discover -s tests`

## การใช้งานโดยย่อ

1. **จัดการบัญชี** — เพิ่ม/เปลี่ยนชื่อ/เรียงลำดับ/ปิดใช้งาน **กลุ่ม** และ **บัญชี**, ย้ายบัญชีข้ามกลุ่ม,
   และกำหนด **บทบาท** ให้บัญชีเงินเดือน, A-1, A-2, A-3, LH (ต้องกำหนดครบจึงจะจัดสรรได้)
2. **ตารางรายเดือน** — เดือนละ 1 คอลัมน์ (Enter/↓ ไปช่องถัดไป, Esc ยกเลิก, คลิกขวาใส่หมายเหตุ)
3. **จัดสรรเงินเดือน** (ปลายเดือน หลังจ่ายบัตรเครดิต) — เพิ่มเดือนใหม่ หรือกดปุ่มใต้คอลัมน์ของเดือนนั้น:
   1. กรอก: ยอดบัญชีเงินเดือนหลังเงินเดือนเข้า, ยอด A-2 และ A-3 หลังจ่ายบัตร (และเงินที่ค้างไว้ในบัญชีเงินเดือน ปกติ 0)
   2. ระบบแสดงรายการโอนตามลำดับ: A-2 = 36,600 − ยอด A-2 · A-3 = 24,000 − ยอด A-3 · A-1 = 27,000 · **LH = ที่เหลือทั้งหมด**
   3. โอนเสร็จ → ตรวจยอดเดือนนั้นที่ระบบเติมให้ (A-2 = 36,600, A-3 = 24,000, บัญชีเงินเดือน = เงินที่ค้างไว้,
      A-1/LH = ยอดก่อนหน้า + ยอดโอน, บัญชีอื่นยกมา) แก้ได้ทุกช่อง แล้วกดบันทึก
4. **แดชบอร์ด** — ยอดรวม/รายกลุ่ม/รายบัญชี, เปลี่ยนแปลงเทียบเดือนก่อน, ยอด LH เทียบช่วงเงินสำรอง 200,000–300,000 (ข้อมูลเท่านั้น), สรุปการจัดสรร, แนวโน้ม
5. **สำรอง / ส่งออก** — CSV (เปิดใน Excel ได้), JSON สำรองครบชุด (กู้คืนไฟล์ v0.1/v0.2 ได้), ประวัติการแก้ไข

ลิงก์ตรง: `#dashboard`, `#accounts`, `#data`, `#alloc-2026-12` (เปิดหน้าจัดสรรเงินเดือนของเดือนนั้น)

## การตัดสินใจในการออกแบบ

| เรื่อง | ที่ทำไว้ |
|---|---|
| ช่องว่าง vs 0 | ช่องว่าง = ยังไม่บันทึก ไม่นับเป็น 0; ต้องพิมพ์ 0 เองถ้ายอดเป็นศูนย์จริง |
| ยอดรวม / เทียบเดือนก่อน | ความหมายเดิมของ v0.1 — เดือนก่อนหน้า = เดือนล่าสุดที่มียอด และแสดงชื่อเดือนที่เทียบเสมอ |
| เดือนของการจัดสรร | เงินเดือนที่เข้าปลาย ต.ค. → ยอดเดือน พ.ย. |
| บัญชีที่ใช้ในการจัดสรร | ระบุด้วยบทบาทที่ผูกกับ Account ID (ไม่ใช่ชื่อ); การจัดสรรที่ยืนยันแล้วจำบัญชีที่ใช้ไว้ |
| ยอดคงที่ 27,000 / 36,600 / 24,000 | คงที่ตาม spec และบันทึกค่าที่ใช้ไว้กับการจัดสรรทุกครั้ง |
| ยอดโอนติดลบ | ไม่ปรับเป็น 0 — ไฮไลต์และต้องกดยืนยันซ้ำจึงบันทึกได้ |
| ยอดที่ระบบเติมให้ (⇄ จัดสรร, ↻ ยกมา) | แก้ได้ทุกช่อง; ค่าที่แก้เป็น “กรอกเอง” และไม่ถูกเขียนทับอัตโนมัติ; ยอดที่กรอกเองอยู่แล้วคงไว้เป็นค่าเริ่มต้นตอนจัดสรร |
| แก้ยอดย้อนหลัง | ยอดอัตโนมัติของเดือนถัด ๆ ไปคำนวณใหม่ต่อเนื่อง (ยกมา = ยอดใหม่, A-1/LH = ยอดใหม่ + ยอดโอนที่ยืนยันไว้) จนเจอยอดที่กรอกเอง — เตือนก่อนบันทึกทุกครั้ง |
| ยอด LH หลังจ่ายงวดบ้าน | ผู้ใช้แก้เอง ระบบไม่คำนวณเรื่องงวดบ้าน |
| ปิดใช้งานกลุ่ม | ต้องย้าย/ปิดใช้งานบัญชีในกลุ่มก่อน; ประวัติยังอยู่ครบ |
| บัญชีที่อัปเดตไม่บ่อย | กด “ยกยอด” ได้ (เครื่องหมาย ↻) จนกว่าจะพิมพ์ยอดจริง |
| หนี้สิน/บัตรเครดิต | รับยอดติดลบได้ ยังไม่แยกประเภทหนี้ (รอยืนยัน) |
| ความแม่นยำ | เก็บเป็นสตางค์ (จำนวนเต็ม) ทศนิยมได้ไม่เกิน 2 ตำแหน่ง |
| การแก้ไข | ทุกการเปลี่ยนแปลงถูกบันทึกใน `audit_log` พร้อมค่าเดิม; ลบเดือนได้เฉพาะเดือนว่าง |

ยังไม่ได้ทำ: นำเข้าจาก Excel เดิม (รอดูไฟล์จริง)

## โครงสร้าง

```
server.py          HTTP server + JSON API (stdlib)
finance/core.py    schema/migration, validation, การคำนวณ, export/backup/restore
static/            หน้าเว็บ (HTML/CSS/JS ไม่ใช้ framework)
tests/             unit tests ตาม acceptance criteria
```

**สำหรับ Module 2/3 ในอนาคต:** เพิ่มตารางใหม่ผ่าน migration ใน `core.migrate()` (ใช้ `PRAGMA user_version`)
และอ้างอิง `accounts.id` / `balances(account_id, period)` / `allocations(period)` — ห้ามเปลี่ยนความหมายของยอดรวมและส่วนต่างรายเดือน
ทดสอบ migration กับสำเนาข้อมูลจริงก่อนใช้งานเสมอ
